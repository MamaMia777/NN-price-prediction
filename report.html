Predicting the Direction of AAPL Daily Returns with a Feed-Forward Neural Network¶

Goal. Predict whether the next daily return of Apple Inc. (AAPL) will be positive, using only lagged returns as inputs. We compare network architectures and optimizers (SGD, Adam, L-BFGS), analyse convergence, evaluate on an untouched test period, and compare a neural-network trading strategy against buy-and-hold.

Design principles. KISS: one library (scikit-learn) does everything, including all three optimizers. YAGNI: no deep-learning framework, no hyper-parameter search beyond what the task asks for. DRY: one helper (cv_report) is reused for every model comparison, and one helper (perf) for every strategy.

1. Data preparation¶

Data. Adjusted daily close prices of AAPL from Yahoo Finance (auto_adjust=True adjusts for splits and dividends). The download is cached in data/AAPL.csv, so re-running the notebook uses exactly the same data.

Definitions.

  • Daily (simple) return: $r_t = \dfrac{P_t}{P_{t-1}} - 1$
  • Input vector of 10 lagged returns: $x_t = (r_{t-1}, r_{t-2}, \dots, r_{t-10})$
  • Target: $y_t = \mathbb{1}\{r_t > 0\}$ (1 = Up, 0 = Down)

All inputs are known at the close of day $t-1$, so a forecast of $y_t$ can be traded at that close — there is no look-ahead.

Why AAPL? It is one of the most liquid stocks in the world (tight spreads → low, realistic transaction costs), it has a long, clean price history, and it is widely studied, which makes it a good stress test of the "returns are hard to predict" hypothesis. (MSFT is excluded by the task.)

2. Chronological experimental design¶

Observations stay in time order — no shuffling anywhere.

  1. Model-fitting period = first 80% of observations. All model choices (optimizer, architecture) are made here using time-series cross-validation (TimeSeriesSplit, 5 expanding-window folds): each fold trains on the past and validates on the block that immediately follows it.
  2. Final test period = last 20%. It is touched exactly once, in Section 6.

Inputs are standardised with a StandardScaler placed inside a pipeline, so the scaler is re-fitted on each training fold only (no information from the validation/test data leaks into the scaling).

Metric. Balanced accuracy $=\tfrac12(\text{TPR}+\text{TNR})$. Because Up days are more frequent than Down days, plain accuracy would reward a model that always says "Up". Balanced accuracy of such a model is exactly 0.5, so 0.5 is the no-skill benchmark.

3. Neural network and optimizer comparison¶

Model (scikit-learn MLPClassifier):

$$\hat p_t = \sigma\!\big(w_3^\top\, \mathrm{ReLU}(W_2\, \mathrm{ReLU}(W_1 x_t + b_1) + b_2) + b_3\big)$$

  • two hidden layers, 32 and 16 neurons (baseline), ReLU activation — simple, avoids vanishing gradients;
  • logistic (sigmoid) output → $\hat p_t = P(y_t = 1 \mid x_t)$; class prediction $\hat y_t = \mathbb 1\{\hat p_t > 0.5\}$;
  • objective: binary cross-entropy (log loss) plus a small L2 penalty (alpha = 1e-4, sklearn default).

Optimizers — all three are built into scikit-learn, so no substitution is needed:

solver what it is iteration counter n_iter_ means
sgd mini-batch stochastic gradient descent (batch 200, lr 0.01, momentum 0.9) epochs (passes over the data)
adam adaptive-moment SGD (lr 0.001) epochs
lbfgs full-batch quasi-Newton method (limited-memory BFGS) L-BFGS iterations

Note: sklearn's sgd uses mini-batches with momentum, the standard practical form of SGD (not single-sample "pure" SGD). L-BFGS uses the full training set per step, so its iterations are not directly comparable to SGD/Adam epochs — we therefore also report wall-clock time. All solvers stop at MAX_ITER = 300 or when the training loss stops improving by more than tol = 1e-4 for 10 consecutive epochs.

The helper below runs time-series CV for any model and reports exactly the quantities the task asks for. It is reused for every comparison (DRY).

def make_model(hidden=(32, 16), solver="adam", **kw):
    '''Standardise inputs -> MLP. Only `hidden` and `solver` change between experiments.'''
    if solver == "sgd":
        kw = {"learning_rate_init": 0.01, "momentum": 0.9, **kw}
    mlp = MLPClassifier(hidden_layer_sizes=hidden, activation="relu", solver=solver,
                        max_iter=MAX_ITER, random_state=SEED, **kw)
    return make_pipeline(StandardScaler(), mlp)


def cv_report(models):
    '''Time-series CV for a dict {name: model}; returns one summary row per model.'''
    rows = {}
    for name, model in models.items():
        t0 = time.perf_counter()
        cv = cross_validate(model, X_fit, y_fit, cv=tscv, scoring="balanced_accuracy",
                            return_train_score=True, return_estimator=True)
        rows[name] = {
            "train_bal_acc": cv["train_score"].mean(),
            "val_bal_acc":   cv["test_score"].mean(),
            "val_bal_acc_std": cv["test_score"].std(),
            "time_s":        time.perf_counter() - t0,
            "mean_n_iter":   np.mean([est[-1].n_iter_ for est in cv["estimator"]]),
        }
    return pd.DataFrame(rows).T.round(4)

5. Convergence analysis (SGD and Adam)¶

We train the baseline 32-16 network one epoch at a time (partial_fit) on the training block of the last CV fold and, after every epoch, record

  • the training loss (log loss + L2 penalty, loss_), and
  • the validation balanced accuracy on the fold's chronological validation block.

(sklearn's built-in early_stopping would use a random validation split, which breaks time order — so we do it by hand.)

In [9]:
def learning_curve(solver, epochs=MAX_ITER):
    tr, va = list(tscv.split(X_fit))[-1]
    scaler = StandardScaler().fit(X_fit.iloc[tr])
    Xtr, Xva = scaler.transform(X_fit.iloc[tr]), scaler.transform(X_fit.iloc[va])
    mlp = make_model(solver=solver)[-1]                      # same MLP settings, without the scaler
    loss, score = [], []
    for _ in range(epochs):
        mlp.partial_fit(Xtr, y_fit.iloc[tr], classes=[0, 1])
        loss.append(mlp.loss_)
        score.append(balanced_accuracy_score(y_fit.iloc[va], mlp.predict(Xva)))
    return pd.DataFrame({"train_loss": loss, "val_bal_acc": score}, index=pd.RangeIndex(1, epochs + 1, name="epoch"))

7. Investment strategy¶

  • Buy and hold: $R^{BH}_t = r_t$.
  • NN directional strategy: hold the stock only when the network predicts Up, otherwise hold cash (zero return): $s_t = \mathbb 1\{\hat p_t > 0.5\}$, $\;R^{NN}_t = s_t\, r_t$.
  • After transaction costs: each change of position (buy or sell) costs $c = 10$ bp: $R^{NN,c}_t = s_t\, r_t - c\,|s_t - s_{t-1}|$ (we assume the strategy starts in cash, so entering costs $c$ too).

Because $s_t$ depends only on returns up to $t-1$, the position can be set at the previous close — no look-ahead. Growth of one monetary unit: $W_T = \prod_t (1 + R_t)$.

def perf(R, days=252):
    '''Standard performance summary of a daily return series.'''
    wealth = (1 + R).cumprod()
    return pd.Series({
        "final wealth (1 →)": wealth.iloc[-1],
        "ann. return":        wealth.iloc[-1] ** (days / len(R)) - 1,
        "ann. volatility":    R.std() * np.sqrt(days),
        "Sharpe (rf=0)":      R.mean() / R.std() * np.sqrt(days),
        "max drawdown":       (wealth / wealth.cummax() - 1).min(),
    })


perf_table = strategies.apply(perf).T.round(4)
perf_table["time in market"] = [1, pos.mean(), pos.mean()]
perf_table["# trades"] = [1, trades.sum(), trades.sum()]
perf_table.to_csv(RES / "strategy_performance.csv")

8. Conclusions¶

(Numbers below come from the executed run with the settings in Section 0 and SEED = 42.)

Data. AAPL, 2015-01-20 → 2024-12-31, 2,505 daily observations; 53.3% Up / 46.7% Down. Fitting period 2015–2022 (2,004 obs), test period 2023–2024 (501 obs, 56.3% Up).

Optimizers (32-16 net, 5-fold time-series CV). All three fit the training data well above chance: L-BFGS ≈ 0.99, Adam ≈ 0.79, SGD ≈ 0.72 training balanced accuracy. But mean validation balanced accuracy is ≈ 0.50 for all of them (SGD 0.494, Adam 0.498, L-BFGS 0.496), i.e. no skill. L-BFGS is the fastest here (small data set, full-batch quasi-Newton) and the strongest at memorising noise. SGD and Adam usually hit the 300-epoch cap (mean n_iter_ ≈ 255 and 295), so the loss is still slowly falling when they stop. Adam has the highest validation score, so it is selected — but the differences (≈0.004) are much smaller than the fold-to-fold standard deviation (≈0.02), so this choice is essentially arbitrary.

Architectures (Adam). Larger networks overfit more (training bal. acc. 0.66 → 0.96 from 16-8 to 64-32-16) without better validation results. 64-32 gives the best mean validation score (0.507) and is selected; the deeper 64-32-16 is the worst (0.488). Again, all differences are within about one standard deviation of zero skill.

Convergence. For both SGD and Adam the training loss falls steadily (0.78 → 0.54 for SGD, 0.78 → 0.48 for Adam; Adam descends faster). Validation balanced accuracy peaks early (SGD ≈ 0.53 at epoch ≈ 45, Adam ≈ 0.52 at epoch ≈ 74) and then drifts back to ≈ 0.50. This is the classic overfitting pattern: after the first few dozen epochs the network fits noise in past returns, not a repeatable signal. (Picking the "best" epoch from one fold's curve would itself be overfitting the validation data, so we did not do it.)

Final test (untouched 2023–2024). Accuracy 0.527, balanced accuracy 0.519. The naive "always Up" rule has a higher accuracy (0.563) because the test period was a bull market. A balanced accuracy of 0.519 on 501 days is only ≈ 0.8 standard errors above 0.5 (SE ≈ 0.5/√501 ≈ 0.022) — not statistically meaningful. Conclusion: lagged returns alone give no meaningful out-of-sample predictive improvement for AAPL, consistent with weak-form market efficiency.

Investment strategy. Buy and hold turned 1 into 2.02 (Sharpe 1.77). The NN strategy was in the market only 57% of days: before costs it turned 1 into 1.65 (Sharpe 1.58) with lower volatility and a smaller drawdown — mostly because it simply holds less stock, not because it times the market well. It changed position 257 times in 501 days; at 10 bp per trade costs cut the result to 1.27 (Sharpe 0.81) and made the drawdown worse than buy and hold. Buy and hold dominates the neural-network strategy both before and after transaction costs.

Limitations. One stock, one seed and one test window; results can change with the seed or period. Only lagged returns are used (by design); volume, market-wide and macro variables might add information, but that is outside this task.
